02 / 개념 이해

이름표에 칸을 세 개 더 만든다고 생각하세요.

이름은 “이 서버가 무엇인지” 알려줘요.
태그는 “어느 묶음에 속하는지” 알려줘요.

서버 이름이 제각각이어도 같은 실습의 리소스라면
Project=mission으로 함께 찾을 수 있어요.

Project항목 이름 · Key
=
mission붙일 내용 · Value
Project

어느 작업인가요?

같은 실습에서 만든 서버·디스크·네트워크를 한 묶음으로 구분해요.

Project = mission
Owner

누가 담당하나요?

관리 담당자를 식별하는 라벨이에요. 이 값을 붙인다고 IAM 권한이 생기지는 않아요.

Owner = cloud-lab
Environment

어떤 환경인가요?

연습용인지 실제 운영용인지 구분해요. 이 예시에서 lab은 실습 환경이에요.

Environment = lab

위 값은 다음 실습에 사용할 수 있는 예시입니다. 과거 리소스에 실제로 붙였던 값이라는 뜻은 아닙니다. AWS 태그 설명 ↗

04 / 보완 방법

다음 실습에서는 세 가지만 더하면 돼요.

이번 리소스는 이미 삭제했으므로, 다음 실습의 기준과 확인 절차로 준비합니다.

1

기준을 정하기

태그 이름과 값, 적용할 대상을 문서에 정해요. 같은 실습은 같은 값을 사용합니다.

준비물: 공통 태그 기준표
2

붙이고 확인하기

태그를 지원하는 실습 리소스에 적용해요. EC2뿐 아니라 EBS와 네트워크도 각각 확인합니다.

준비물: 리소스별 태그 화면
3

증거를 남기기

태그 필터 결과와 기존 ID 목록을 비교하고, 확인 화면을 보관한 뒤 체크리스트에 기록해요.

각 리소스에 누락이 없는지 확인합니다.

문서로 정한 운영 규칙 예시입니다. AWS에 적용하거나 IAM으로 강제한 정책은 아닙니다. Owner 값은 담당자를 표시하는 예시입니다.
IAM 파일에 CreateTags가 있는데, 이미 정책이 있는 건 아닌가요?

현재 IAM 파일의 ec2:CreateTags는 태그를 붙이는 작업을 허용합니다. 태그를 붙일 수 있는 권한과 반드시 특정 태그를 붙여야 한다는 규칙은 달라요. 현재 파일에는 Project·Owner·Environment를 필수로 검사하는 조건이 없습니다.

태그를 붙이면 비용도 바로 프로젝트별로 보이나요?

비용 보고서에 사용자 정의 태그를 사용하려면 Billing에서 비용 할당 태그 활성화도 필요해요. 태그를 붙였다는 사실과 비용 보고서에서 분류되는지 확인한 사실을 따로 기록합니다. 활성화와 데이터 반영에 시간이 걸릴 수 있어요. 이번 실습에서는 이 설정을 완료했다는 기록이 없습니다. AWS 비용 할당 태그 안내 ↗

지금 문서에 “태그 적용 완료”라고 추가해도 되나요?

현재 자료에는 공통 태그 적용 증거가 없고 실습 리소스도 이미 정리했습니다. 따라서 “향후 실습에 적용할 보완 기준”으로 적는 것이 정확해요. 실제 완료 표시는 다음 실습에서 적용과 검증을 마친 뒤 남깁니다.
